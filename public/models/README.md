# Local GLB models (`public/models/`)

Drop optimised **glTF/GLB** models here to replace procedural placeholders with
real assets — one id at a time. Offline-first: files are served locally, never
from a CDN.

## How to add a model
1. Optimise the GLB for WebGL (low poly, KTX2/Draco/meshopt where possible).
2. Save it here as `<id>.glb`, e.g. `sofa-3seat.glb` or `philips-hue-go.glb`
   (the `<id>` is the furniture/device id used in the app).
3. Register it in `src/assets/modelRegistry.ts`:
   ```ts
   export const MODELS = {
     'sofa-3seat': { file: 'sofa-3seat', nominal: [2.2, 0.95] },
   }
   ```
4. That id now renders the GLB (lazy-loaded); everything else stays procedural.
   A missing/broken file falls back to the procedural mesh automatically.

## Fitting a model to the placed footprint
Furniture is resizable (`PlacedFurniture.size`), and a GLB used to ignore that
completely: the procedural fallback was built to the placed width/depth, but a
registered model rendered at whatever size it was authored at, while the
selection ring and the 2D plan followed the real footprint. Replacing a
placeholder with a real asset therefore broke resizing for that id.

`nominal` fixes it — the footprint in metres the asset was authored at:

| `fit` | behaviour |
|---|---|
| `stretch` (default when `nominal` is set) | scales X/Z to the placed footprint, keeps the height |
| `uniform` | one factor on all axes, for anything whose proportions must not change |
| `none` (default without `nominal`) | renders at the authored size |

The CC0 assets below carry no `nominal`, so they behave exactly as they always
have.

## Rules
- **Licence:** only commit models you may redistribute — your own files, CC0
  (e.g. Poly Haven), or assets generated by `tools/blender`. Do **not** commit
  branded/3rd-party models without a redistribution licence.
- **Scale:** model units are treated as metres; use `nominal`/`scale`/`offset`.
- **Budget:** keep each asset small; watch bundle size and load time. The GLTF
  loader is only bundled once at least one model is registered.

Untextured, so all 22 together are ~750 KB — less than half of one textured CC0
armchair. Each is a single joined mesh with two to four material slots, against
the ~20 separate meshes its procedural fallback draws.

Rebuild with `python3 tools/blender/build.py` (or `blender --background
--python tools/blender/build.py`). `tools/blender/manifest.json` records what
each build produced and is asserted against the registry and the furniture
catalog by `src/assets/modelRegistry.test.ts`.

## Two sources, two namespaces

There are two asset pipelines, and they are good at different things. They write
to **separate directories** so they can never overwrite each other — an earlier
merge had both emitting `barstool.glb`, and whichever ran last won.

| | `public/models/*.glb` | `public/models/scan/*.glb` |
|---|---|---|
| Built by | `tools/blender` | `scripts/assets/` |
| What | parametric furniture authored to the catalogue's dimensions | CC0 photoscans (Poly Haven) |
| Textures | none — flat materials | full PBR sets (albedo, normal, ARM) |
| Size | 15–110 KB | 130–660 KB |
| Fit mode | `stretch` — geometry is authored, so it widens cleanly | `uniform` — stretching a capture smears its texture |
| Footprint | `nominal` in the registry, from `tools/blender/manifest.json` | measured into `src/assets/modelSizes.ts` by the build |

Where both cover an id, **the generated model currently wins**: its footprint is
held to the catalogue by a test and it stretches when a piece is resized.
Swapping one for the photoscan under `scan/` is a deliberate look decision — the
photoscan is far more convincing and cannot be stretched — not something to do
by accident.

### Building the photoscans

```bash
node scripts/assets/fetch.mjs --all     # download CC0 sources → assets-src/
node scripts/assets/build.mjs           # normalise + optimise → public/models/scan/
```

`build.mjs` regenerates `src/assets/modelSizes.ts`; commit it with the models.

| Stage | Tool | Job |
|---|---|---|
| `normalize.py` | Blender (headless, `pip install bpy`) | orient · centre · seat on floor · fit to the catalogue footprint |
| `optimize.mjs` | gltf-transform | dedup · join · WebP · Draco |

Measured on the first six: **7.79 MB → 1.31 MB (−83 %)** with the triangle count
untouched — the whole saving was textures, which arrived as uncompressed 1024²
maps. Draw calls fell too (the desk went from 9 to 1).

These are Draco-compressed with Draco marked *required*, so they need the
decoder in `public/draco/`. It is self-hosted deliberately: drei defaults to a
Google CDN, and offline they would not degrade — they would fail to load.

### Mounted, not standing

Both pipelines seat assets on the floor. For anything hung, set `anchor` in the
registry (`'ceiling'` for a pendant, `'wall'` for a mirror); the offset is
derived from the model's *fitted* height, so a pendant scaled to a smaller
footprint still reaches the same ceiling.

### A caveat on coverage

The catalogue has 97 furniture types and 172 devices. Poly Haven — the only CC0
source used — leans heavily antique, rustic and industrial: carved sofas, gothic
chairs, distressed cabinets, CRT televisions. Roughly two thirds of the obvious
name matches were rejected because they would look *worse* in a modern
smart-home plan than the mesh they replaced. Covering the rest at photoscan
quality needs a licensed modern interior library, not more scripting.
